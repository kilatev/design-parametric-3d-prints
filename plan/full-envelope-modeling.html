Deferred: Full-envelope modeling

Idea

Model the complete inserted object's envelope, not just its nominal width/diameter: phone + case, connector + cable body, cable bend radius, grip/clip protrusion, and finger clearance needed to remove the part. Surface these as extra parameters (e.g. case_thickness, cable_bend_radius, finger_clearance) so the preliminary drawing shows the real fit, not just the bare object.

Why deferred

references/engineering-checklist.md §1 already asks "what nominal width... must fit" and §2 already requires showing "object-fit envelopes and clearances, not only the plastic around them" — this is largely already covered by existing process. What's missing is task-specific: it only matters for parts that actually hold a case/connector/cable, and the extra parameters differ per object. A generic schema field would mostly go unused.

When to build it

If a delivered part repeatedly turns out too tight because a case or connector body wasn't accounted for — i.e. after it causes a real revision, not preemptively.

What it would touch

  • references/engineering-checklist.md §1 — add explicit prompts for "object + accessory (case/cable/connector)" envelope when the object has one.
  • Per-task parameters.json — add the extra envelope dimensions inline (no schema change needed; the schema is already open).
