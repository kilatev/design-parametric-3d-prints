Deferred: Slicer pre-check step

Idea

Add a final delivery step: import the STL into an actual slicer (headless CLI, e.g. PrusaSlicer/OrcaSlicer), confirm no auto-generated supports appear where none were designed, check first-layer footprint, flag thin walls, estimate print time/material, and optionally export a sliceable .3mf project.

Why deferred

This duplicates work the slicer already does well, and wiring a specific slicer's CLI into this skill is an environment dependency (a new tool to install/version, per the ladder's "already-installed dependency" rung — none is installed here) for a check that's easy for the user to run themselves in 30 seconds by opening their usual slicer. The skill's own STL validator already catches the geometry-side failures that would cause unwanted supports (non-manifold edges, floating shells, missing bed contact).

When to build it

If slicer CLI automation becomes available in the environment and repeated manual re-slicing turns out to be the actual bottleneck.

What it would touch

  • A new optional script, e.g. scripts/slice_precheck.py, wrapping whichever slicer CLI is installed.
  • SKILL.md §"Validation gates" — add as an optional final step, clearly marked as requiring a locally installed slicer.
